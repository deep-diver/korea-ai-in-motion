# 모바일 전용 화면: 10회 개선 기록

대상: 국가AI전략위원회 독립 사이트. 900px 이하에서는 모바일 구성을 사용하고,
그보다 넓은 화면의 기존 데스크톱 레이아웃·글자 크기·무대 배치는 유지한다.
기본 재생 속도는 2배속이다.

| 회차 | 개선 | 확인 및 보정 |
|---|---|---|
| 1 | 모바일 스타일을 `mobile.css`로 분리하고 데스크톱을 보존 | 1440×1000 전후 캡처의 전체 크기 1440×1591 일치. 차이는 연결선 가장자리의 1픽셀 범위뿐 |
| 2 | 모바일 제목·날짜·분과 선택의 정보 순서를 정리 | 분과 버튼은 44px 터치 영역과 가로 스크롤을 유지하며, 장면 제목은 무대 바로 위에 표시 |
| 3 | 고정 690–860px 무대를 별도 뷰포트로 교체 | 화면 너비와 `svh`에 맞춰 320px 화면의 캔버스 약 282px, 390px 화면 약 343px, 태블릿 440px로 조정 |
| 4 | 인물·오브젝트 설명을 무대 아래 카드로 재구성 | 휴대폰은 세로, 540px 이상은 두 열. 첫 캡처에서 발견한 기존 duo 위치 규칙의 겹침을 제거 |
| 5 | 카드 연결선의 좌표계를 모바일 레이아웃에 맞춤 | 새 제목 영역 높이와 카드 상단 중앙을 반영하고, 카드·무대 크기 변경을 관찰하여 재계산 |
| 6 | 재생·탐색·속도를 스크롤 중에도 조작 | 모바일 상단 sticky 재생 바, 44px 버튼, 320px에서 재생 글자만 접고 접근 가능한 이름은 보존 |
| 7 | 자동 근거 카드가 본문을 덮는 문제 해결 | 모바일에서는 본문 안에 표시. 비활성 순간의 빈 공간을 실제 출처 미리보기로 대체하고 데스크톱 오버레이는 유지 |
| 8 | 세 축 타임라인을 모바일·키보드에 맞춤 | 축 이름의 폭과 줄바꿈을 조정. 레일을 직접 포커스·스크롤할 때 전역 장면 전환 키가 가로채지 않도록 지정 |
| 9 | 가로 화면·노치·작은 화면 대응 | `svh`/`dvh`, 좌우 safe-area, 작은 화면의 컨트롤 간격과 대화상자 크기를 보정 |
| 10 | 터치와 여러 장면에서 종합 재검증 | 320×740, 390×844, 768×1024, 844×390에서 가로 넘침/런타임 오류 0. 대표 10개 장면에서 카드 겹침 0. 실제 터치 입력으로 캔버스 세로 스크롤, 다음, 속도, 타임라인 키보드, 탐색·다시 보기 검증 |

## 재현 가능한 검증 범위

- 대표 장면 인덱스(0부터): 0, 1, 10, 20, 25, 30, 35, 42, 49, 52.
- 레이아웃 캡처에는 동작 줄이기를 사용해 완성된 장면의 좌표를 비교했다.
- 별도의 일반 재생 환경에서 초기 2×, 일시정지, 세로 터치 스크롤과 입력을 확인했다.
- 390px 화면에서 기록 대화상자 전체가 뷰포트 안에 들어오는 것을 확인했다.
- 캡처·좌표·터치 검증 결과는 로컬 `outputs/mobile-review/`에 보관하며 웹 배포에는 포함하지 않는다.
